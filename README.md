# Мастерская

## Общая ведомость инвентаризации и защита данных

В разделе **«Материалы» → «Инвентаризация»** можно пересчитать несколько материалов за одно действие. Для каждого материала показывается учётный остаток; в столбце «Фактически» введите обнаруженное количество. **Пустое поле** означает «не проверял», **0** означает нулевой фактический остаток. Поиск фильтрует строки, но не стирает ранее введённые значения.

- До сохранения ведомости выводятся количество проверенных материалов, расхождения и изменение учётной стоимости.
- Каждая заполненная строка сохраняется как отдельное движение материала с общим **ID ведомости**. История показывает одну запись на всю ведомость, которая раскрывает её строки.
- Недостачи списываются по ФИФО, излишки попадают в виртуальную партию инвентаризации. Списание не изменяет прежние выпуски и не создаёт денежную покупку.
- Перед подтверждением проверяются все строки, затем выполняется единое сохранение в браузере. При ошибке проверки ведомость целиком откатывается из текущего состояния.
- Изменение или удаление старой закупки ограничено, если она относится к периоду уже проведённой инвентаризации данного материала. Редактирование магазина и ссылок остаётся доступно.
- Добавлена проверка JSON при загрузке и импорте. Повреждённая запись в браузере больше не заменяется молча пустой базой: приложение блокирует сохранение, предупреждает и позволяет скачать аварийную копию. При импорте складская история проверяется до записи.
- **Ограничения:** данные по-прежнему хранятся локально на устройстве, не синхронизируются между браузерами и не имеют автоматических серверных резервных копий. Аварийная копия может содержать повреждённые данные и не гарантирует восстановление. Регулярно скачивайте JSON.

Для обновления с реальными данными сначала экспортируйте JSON из текущей версии, затем откройте новую. Проверены контрольные сценарии нескольких материалов, нулевого остатка, совместимость старой JSON-структуры, аварийный запуск и JavaScript; полный визуальный регрессионный тест мобильного и настольного браузеров ещё не проведён.

## Инвентаризация материалов

В «Материалах» откройте «Инвентаризация». Выберите материал и укажите **фактически найденное количество**, а не разницу. Например, если по учёту 60 листов, а фактически 58 — введите 58. Для нулевого остатка укажите 0. Заполните причину и сохраните.

- Перед сохранением показываются расчётный остаток, фактический остаток, отклонение и изменение учётной стоимости.
- Недостача списывается из доступных партий сырья по ФИФО. Излишек создаёт отдельную внутреннюю партию по средней стоимости текущего остатка; если запаса нет, используется последняя закупочная цена. Без известной цены излишек не проводится.
- Расхождения не создают закупку или продажу и не меняют прошлые цены выпущенных изделий. Результат влияет на стоимость текущего сырьевого запаса.
- История инвентаризаций остаётся в приложении и в резервных копиях JSON. Ошибочную инвентаризацию нужно исправлять новым пересчётом.
- Корректировка или отмена старой производственной партии после инвентаризации того же материала блокируется, чтобы не нарушить подтверждённый остаток.
- Сейчас инвентаризация проводится по **одному материалу за запись**; массовая ведомость, сканирование, серверное хранение и фактические расходы денег за недостачи не реализованы.

**Важно:** это новая функция для реального складского учёта. Проверены синтаксис и контрольные расчёты ФИФО, но не проведён полный браузерный регрессионный тест всех старых данных. Перед работой обязательно скачайте резервную копию JSON и сначала проверьте пересчёт на тестовых данных.

## Учёт сырья по закупочным партиям (ФИФО)

Каждая строка закупки — отдельная партия сырья с собственной датой, количеством и ценой единицы. Доставка распределяется по строкам закупки. При новом выпуске списывается доступный остаток самой ранней закупки, затем следующих; в производственной партии фиксируются источник, количество и стоимость каждой части.

Пример: две упаковки по 50 листов за 450 ₽ и 600 ₽. Если из первой осталось 10 листов, а для открыток нужно 40, списываются 10 × 9 ₽ + 30 × 12 ₽ = 450 ₽. На второй закупке остаётся 20 листов.

- В карточке материала показаны остатки и цена по каждой закупке.
- В карточке нового выпуска отображается, какие закупки были использованы.
- Уже сохранённые старые выпуски **не получают новую себестоимость**. Приложение восстанавливает их количественное потребление по ФИФО для определения остатков; точно восстановить фактический источник старых списаний без архивных записей нельзя.
- Запрещено удалять закупку или менять её дату, цену, количество, если материалы уже списаны из неё. Поставщика и ссылки на товар изменить можно.
- Выпуски, датированные раньше необходимой закупки, блокируются.
- В предварительных калькуляциях при нехватке остатка недостающая часть оценивается по последней известной цене, но сам выпуск запрещает отрицательный остаток.
- Перед продолжением работы с реальными записями сохраните JSON-копию. ФИФО сейчас ещё не проходил полноценный тест в работающем браузере с реальными данными пользователя.

## План закупок по будущим изделиям

В разделе «Производство» нажмите «Спланировать закупки» (или «План закупок» на главной). Добавьте несколько изделий и укажите количество. Приложение суммирует потребность по всем рецептурам, сравнит её со складскими остатками и отдельно покажет рекомендованное количество к покупке с учётом установленного минимального запаса.

- Учитываются листы, граммы, миллилитры, проценты и капли согласно текущей рецептуре; материалы с одинаковым ID суммируются.
- Если закупались упаковки и есть их размер, показывается ориентировочное количество упаковок по последней закупке.
- Цена покупки — оценка по средней учётной цене материалов, без расчёта фактической новой корзины, специальных цен и доставки.
- Ссылки на карточки товаров и название поставщика показываются, если они сохранены в последней закупке.
- Список покупок можно выгрузить в текстовый файл. План **не изменяет** склад, не резервирует материалы, не создаёт заказ поставщику и не оформляет выпуск.
- Перед обновлением рабочей версии рекомендуется экспортировать JSON в «Настройках». Данные по-прежнему находятся в локальном хранилище браузера; автоматических серверных резервных копий пока нет.

## Ссылки на товары и понятные виды покупок

- В каждой строке закупки материалов можно указать полную ссылку на карточку товара (Ozon, Wildberries или другой поставщик). Поставщик/магазин задаётся на уровне всей закупки; ссылки — индивидуально для каждой позиции.
- Ссылки доступны в карточке сохранённой закупки; при редактировании они не теряются. Старые закупки без ссылок продолжают работать.
- В разделе «Оборудование и расходы» есть отдельное поле ссылки на покупку.
- Тип «Хозяйственный расходник» переименован в «Расходник для работы» без изменения хранимого значения `consumable`.
- Ссылки ограничены адресами HTTP/HTTPS и открываются в новой вкладке. Публичный сайт не копирует описание, цены и остатки торговых площадок автоматически.

## Операции с оборудованием и хозяйственными расходниками

В карточке изделия, в блоке «Операции и оплата труда», можно привязать к операции одну единицу оборудования и один хозяйственный расходник, ранее зарегистрированные в разделе «Оборудование и расходы». Для каждой покупки нужно указать цену и плановый ресурс в количестве использований.

- Для операции «На 1 шт.» доля стоимости покупки начисляется за каждое изготовленное изделие (включая брак).
- Для операции «На всю партию» доля стоимости покупки начисляется один раз на выпуск.
- В расчёте и производственной партии появляется отдельная строка «Техника и расходники». Исторические партии и сохранённые калькуляции не пересчитываются из-за последующего изменения стоимости покупок.
- При корректировке не проданной партии используются зафиксированные ставки ранее сохранённого выпуска. Удаление покупки, связанной с текущей операцией изделия, заблокировано.

**Ограничения:** это плановое распределение расходов, а не отслеживание остатка чернил, фактического ресурса принтера или бухгалтерская амортизация. Покупки уже полностью учитываются в денежном отчёте; распределённые доли нельзя вычитать из него повторно. Если фактические чернила и другие расходуемые ингредиенты требуется списывать по количеству, используйте раздел «Материалы», не регистрируя одну и ту же покупку дважды. Доли техники при оформлении выпуска больше не требуется вручную записывать в «Прочие расходы».

## Обновление: вложения и окупаемость (15 ноября 2026)

- Появился общий раздел **«Оборудование и хозяйственные расходы»**. Покупки классифицируются как оборудование, хозяйственный расходник или прочий расход. Старые покупки оборудования сохраняют свою категорию.
- На главной странице выводятся расходы на закупку производственных материалов, оборудование, расходники, комиссии, доставку и расчётные налоги, поступления от продаж, возвраты, денежный результат и помесячный график.
- «Осталось до окупаемости» — абсолютная величина отрицательного результата зарегистрированных денежных операций. Это **не** валовая прибыль, не показатель денежных средств в банке и не налоговая отчётность.
- Для материалов покупки отражаются целиком при регистрации, а производственные списания и себестоимость реализованных изделий не вычитаются второй раз из денежного результата.
- Денежная модель пока предполагает совпадение даты операции и платежа. Не поддерживаются отсрочки оплаты, кредиты, частичные платежи, реальные выплаты труда и банковские выписки. Налог от выручки только расчётный.
- **Важно:** категория «Хозяйственный расходник» в этом разделе означает прямой расход денег. Покупка чернил не списывается по мл и не включается автоматически в себестоимость. Для количественного учёта краски как материала её нужно заводить в «Материалы», но нельзя одновременно регистрировать покупку в обеих категориях.
- Покупки оборудования пока не привязаны автоматически к операциям производства: этот этап ещё требует реализации.

### Новое в версии 11

- **Контроль запасов:** предупреждение при остатке ниже или точно на установленном минимуме. Список материалов на пороге доступен на главной странице, статус виден в каталоге материалов.
- **Налоги в прогнозах:** в «Настройки» указывается ставка расчётного налога с выручки по умолчанию. В каждой продаже ставку можно изменить; она фиксируется в сохранённой операции. Возвраты уменьшают оценку налога пропорционально сумме возвращённых денег. Ранее проведённые продажи автоматически не пересчитываются.
- **Маржа и наценка:** в калькуляции можно выбрать способ расчёта целевой цены. Для процентной наценки цена рассчитывается на базе себестоимости и учитывает комиссию и расчётный налог; для маржи учитывается желаемая доля прибыли в выручке.
- **Оборудование:** отдельный реестр покупок резаков, принтеров и других инструментов с ориентировочной стоимостью на одно изделие по заданному ресурсу. Стоимость оборудования **не списывается автоматически** в себестоимость: долю можно указать вручную в прочих расходах партии.
- **Расходники:** бумага, чернила, тара и другие расходуемые компоненты по-прежнему учитываются в «Материалах» и списываются по рецептурам и фактическому выпуску.

**Налоговые суммы — только оценка для планирования:** режимы с налогооблагаемой базой «доходы минус расходы», НДС, вычетами и другими исключениями здесь не рассчитываются. Для налоговой отчётности используйте официальный учёт. Все данные приложения пока сохраняются в браузере; перед обновлением сделайте JSON-копию.

## Что работает (версия 11)

- **Закупки и материалы:** покупки в упаковках и отдельных единицах, распределение доставки, справочник категорий, средние закупочные цены, предупреждения о минимальном остатке.
- **Рецептуры изделий:** граммы, килограммы, миллилитры, литры, капли и проценты от массы/объёма одного изделия; пересчёт на тираж. По умолчанию 1 мл эфирного масла ≈ 30 капель, коэффициент можно задать отдельно для материала.
- **Калькуляции:** материалы, работа, прочие затраты, брак, прогноз цены продажи и прибыли. Сохранённые расчёты не изменяются задним числом.
- **Производство:** регистрация завершённой партии, проверка наличия материалов, нормы рецептуры с возможностью указать фактический расход, автоматическое списание со склада, учёт брака, работы и дополнительных затрат.
- **Склад:** поступления минус расход на подтверждённые партии; количество и себестоимость готовых изделий. Отменённый выпуск сохраняется в истории, а его списания исключаются из остатков. Выпуск с уже зарегистрированными продажами отменять нельзя.
- **Продажи:** учёт проданных единиц, цены, комиссии площадки (процент и фикс), доставки за счёт продавца и канала продаж. Себестоимость продажи фиксируется по ранним доступным партиям (ФИФО). При продаже готовые изделия списываются со склада.
- **Возвраты:** отдельная операция, связанная с продажей, с количеством, суммой возврата денег и дополнительными расходами. Пригодный товар можно восстановить на складе по первоначальной себестоимости, повреждённый остаётся списанным.
- **Прибыль:** суммарная выручка за вычетом возвратов, себестоимости реализованных и не вернувшихся на склад изделий, комиссий, доставки и затрат на возвраты. Это результат **по зарегистрированным операциям до налогов и общих расходов**, а не итог движения денег.
- **Резервные копии:** экспорт и импорт JSON, включая историю производства, продаж и возвратов. Данные версий 6 и 7 поддерживаются.

## Как пользоваться

1. Создайте материалы и зарегистрируйте закупку с ценами.
2. Создайте изделие, укажите состав и операции изготовления.
3. Для предварительной цены используйте «Калькуляции».
4. В «Производстве» укажите изготовленное и годное количество, скорректируйте фактический расход ингредиентов, проверьте расчёт и подтвердите выпуск.
5. Проверьте уменьшение остатка в «Материалах» и приход готовых изделий в «Производстве».
6. В «Продажах» укажите количество, цену, комиссию и доставку. Готовые товары спишутся из более ранних партий, а прибыль пересчитается.
7. Если товар вернули, откройте запись продажи и оформите возврат с указанием, пригодно ли изделие для повторной продажи.

Стоимость материала в наличии показана по **средней закупочной цене всех поступлений**. При закрытии партии стоимость расхода и себестоимость годной продукции фиксируются в самой партии. Изменение закупочной цены в будущем не переписывает закрытые партии.

Для процентных рецептур укажите массу или объём изделия. Программа **не переводит граммы в миллилитры без плотности** и не проверяет безопасность косметических составов.

## Что ещё не реализовано

Отслеживание фактических поступлений денег от покупателей, налоги, общие расходы мастерской и точная бухгалтерская отчётность; полноценная инвентаризация и списания готовой продукции по причинам, не связанным с продажами и возвратами; серверная база данных, личные кабинеты, синхронизация между устройствами, платежи и тарифы.

Продажи и возвраты сохраняются в хронологическом порядке для каждого изделия. Записи не редактируются задним числом; исправления продаж в этой версии оформляются возвратом. Суммы налога и общего содержания мастерской нужно учитывать отдельно, прежде чем делать вывод о чистой прибыли.

## Разработка

- `index.html` — клиентское приложение.
- `docs/architecture.md` — план серверной версии.
- `main` + GitHub Pages `/(root)` — публикация приложения.

Новый код публикуется GitHub Pages после обновления `index.html` в `main`. При работе с реальными данными сначала экспортируйте JSON, затем обновляйте сайт. Для учёта продаж финансовые и складские данные должны находиться в одной резервной копии.
