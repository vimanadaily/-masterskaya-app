# Архитектура будущей серверной версии «Мастерской»

Это проектный план. Сервер, личные кабинеты и синхронизация пока не реализованы.

## Изоляция данных
- У каждого пользователя могут быть отдельные мастерские (workspaces).
- Каждая запись о материале, закупке, рецептуре, изделии или продаже принадлежит workspace_id.
- Права: владелец, редактор, просмотр. Проверка на сервере в каждом запросе.
- Для хранения предполагается PostgreSQL с миграциями и резервными копиями.

## Учёт производства
- Закупки и цены материалов, движения склада, версии рецептур, производственные партии, продажи.
- Плановая себестоимость отделяется от фактической.
- Закрытая партия и зафиксированная калькуляция не меняются после изменения закупочной цены.
- Состав рецепта: материал, расход, режим «базовая единица / капли / проценты».
- Проценты используют указанную массу (г/кг) либо объём (мл/л) готового изделия; смешивать массу и объём без плотности нельзя.
- Для эфирных масел коэффициент по умолчанию — 30 капель/мл, настраивается для материала.

## Этапы
1. Стабилизировать локальный прототип и тесты.
2. Реализовать API, авторизацию, хранение данных и перенос JSON.
3. Добавить склад, производственные партии и реальные продажи.
4. Настроить безопасность, управление тарифами и платежи.

Нельзя размещать персональные данные, чеки, JSON-резервные копии и секреты в публичном репозитории.
